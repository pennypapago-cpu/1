## 錄影清單

依錄製順序：

1. **帳號確認**：用有 Skills 入口的 ChatGPT 帳號（跟第 1 集同一個）。錄影前先確認側邊欄看得到 Skills 入口、可以建立 Project。建議使用深色模式、關掉不相關的對話紀錄或用乾淨的帳號，避免畫面出現私人內容。
2. **說明欄文字**：先把下面第 3 項「規則」和 Skills 方案限制的說明（見待確認事項）準備好，上片時放進說明欄（頻道主手動貼）。
3. **規則（第一步貼進 Project 指示欄位）**

```
你是我的會議記錄整理助理。我會貼上會議筆記或逐字稿，請整理成以下五段：

1. 會議資訊：會議名稱、日期、出席者（內容沒有提到就寫「未提供」）
2. 摘要：3 句以內
3. 決議事項：只列已經確定的決定
4. 未定案事項：還在討論、沒有結論的事
5. 待辦事項：用表格，欄位是「事項｜負責人｜期限｜備註」

規則：
- 只根據我提供的內容整理，不要自己補充或猜測。
- 沒有負責人或期限，就填「待確認」。
- 「下週三」「這禮拜內」這類相對日期，依會議日期換算成具體日期，並在備註寫「依會議日期推算，請確認」。
- 一律使用繁體中文、台灣用語。
- 最後加一段「會後要確認的問題」，條列出來。
```

4. **範例筆記 1（第二步貼上：行銷部週會，虛構）**

```
11/4(三) 行銷週會  王經理、小美、阿凱、Jason  (Amy請假)

- 雙11活動檢討:FB廣告點擊OK 但轉換偏低 王經理:LP要檢討
- LP改版 → 阿凱 下週三前出新版 (要先跟小美對文案
- 會員回饋活動 確定12/1上線!!
- 贈品預算 Jason說3萬不夠 至少要5萬 王經理:再看看 下次再決定
- 要不要做抖音? → 先不做 專心經營IG
- 回饋活動文案 小美 11/14前
- 要找KOL 3~5位 誰負責?? 沒講
- 客服FAQ要更新 等Amy回來問她
- 下次開會 11/11 同時間
```

   預期重點（給頻道主對照，實際以輸出為準）：決議＝12/1 上線、先不做抖音、11/11 開下次會；未定案＝贈品預算；待辦中「找 KOL」負責人與期限待確認、「LP 改版」期限「下週三」推算為 11/11 並註明請確認、「客服 FAQ」負責人待確認（不應直接寫成 Amy）。

5. **請 GPT 寫 SKILL.md 的指令（第三步貼上）**

```
請把這個 Project 的會議記錄規則，整理成一份 SKILL.md。
名稱用 meeting-notes。
說明要寫清楚什麼時候使用這個 Skill：當我貼上會議筆記、會議逐字稿，或是說「幫我整理會議記錄」的時候。
內容保留五段格式和所有規則，用繁體中文。
```

6. **錄 Skills 介面建立流程**：依當下介面操作，把上一步的 SKILL.md 內容建立成 Skill（可能是用對話建立、編輯器貼上或上傳檔案，挑當下最直覺的一種錄）。錄到看見 Skill 出現在清單為止。
7. **範例筆記 2（第四步貼上：尾牙籌備會逐字稿，虛構）**


8. **計時器**：第四步從按下送出到輸出完成，錄影時開碼表或剪輯時疊計時器，記下實際秒數給包裝師。
9. **第 3 集預告畫面**：簡單錄一次「請 GPT 依待辦表格寫三封追蹤信草稿」的結果當預告素材即可，不用做成 Skill。
10. **插圖素材**：Prompt vs Skill（口頭交代 vs 桌上 SOP）、範本 vs Skill、以前 vs 現在對比圖、延伸應用四格圖卡。

## 給包裝師的重點

- **最強的「以前 vs 現在」**：以前手動整理會議記錄 20 到 30 分鐘（頻道主自述，錄影後確認）vs 現在貼上筆記，不到 1 分鐘（以第四步實測秒數為準，不要寫沒測過的數字）。
- **觀眾最在意的結果**：亂七八糟的筆記→整齊的「摘要／決議／待辦（負責人＋期限）」；而且 AI「不亂猜」，沒講的會標「待確認」。這是跟一般「叫 GPT 摘要」最大的差異，可以當標題角度。
- **縮圖畫面**：左邊放範例筆記 1 的原始亂筆記（黃色），右邊放整理後的待辦表格（藍色），表格中「待確認」用醒目色圈起來。
- **系列感**：標題或縮圖角落可帶「Skill 系列 2」，讓第 1 集觀眾認得；第 1 集標題〈別再重複教GPT！Skill一次搞定〉是目前最佳長片，可沿用「別再……！」句型。
- **標題方向參考**：「會議記錄還在手打？GPT Skill一鍵整理好」「開完會不用再整理！GPT會議記錄Skill」（30 字內、帶上班族情境）。
- **片尾畫面**：建議連到第 1 集（沒看過的人補課）。

## 待確認事項

1. **方案限制（重要）**：OpenAI 說明文件〈Skills in ChatGPT〉的搜尋摘要寫 Skills 開放給「符合資格的 ChatGPT Business、Enterprise、Healthcare、Edu 使用者」，並受工作區設定影響。Plus／Pro 個人帳號在一般對話能不能用，目前沒看到官方明確說法；社群有 Plus 使用者回報個人 Skill 在一般對話叫不出來。錄影前請頻道主確認自己帳號的實際情況，說明欄的方案說明以當下官方頁面為準。口白只說「Skills 目前有方案限制」。
2. **入口與按鈕名稱**：搜尋摘要提到入口在側邊欄的 Plugins，Plugin Directory 裡的 Skills 分頁，建立方式有 Create with chat、Create with editor、Upload from your computer，帳號預設附一個 skill-creator。這些名稱我是從搜尋摘要和第三方文章看到的，沒辦法直接開官方頁面核對，中文介面的名稱也可能不一樣，所以口白一律寫「依照 Skills 介面的操作建立」。
3. **叫出 Skill 的方式**：OpenAI Academy 和開發者訓練頁的搜尋摘要提到可以在輸入框打 @ 選取，ChatGPT 也可能自動套用相關的 Skill。實際操作以錄影當下為準，所以口白只說「叫出 Skill」。
4. **Project 指示欄位的名稱**：口白寫「Project 的指示欄位」，請照實際介面上的名稱調整字卡。
5. **SKILL.md 名稱格式**：名稱能不能用中文、有沒有格式限制沒有確認，腳本先用英文 `meeting-notes`，比較不容易出錯。
6. **地區限制**：沒有查到台灣地區有特別限制的官方說明，未確認。
7. **頻道主的個人例子**：開場 A 的「週會筆記亂」、第四步的「以前要二、三十分鐘」、開場 B 的「記錯負責人」，都是我假設的情境，要換成頻道主真實的經驗跟數字。
8. **AI 輸出不保證**：第二步、第四步口白描述的結果（例如「下週三」換算成 11/11），是照規則推出來的預期，實際輸出以錄影為準。沒做到的地方，就照腳本示範補一句規則再測。
9. **說明欄**：口白提到「規則放在說明欄」「方案資訊放在說明欄」，上片時記得貼上（由頻道主手動處理）。
10. **第 3 集可行性**：「會後追蹤信 Skill」只產生 Email 草稿，寄信由使用者自己來，不需要串接其他服務，用目前的 Skills 功能應該做得到（推估）。如果第 3 集想做成自動寄信，就需要另外確認 Gmail 等連接器能不能用、有沒有方案限制。
11. **網路限制**：這次 help.openai.com 和 openai.com 在工作環境中無法直接開啟，以上官方資訊都來自搜尋結果的摘要。需要逐字核對的話，要在 session 網路設定中允許這兩個網域，或請頻道主自己開頁面確認。
